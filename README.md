# DSP Practical Progression Guide

I originally made this guide for myself and thought it might help others. You
are welcome to use and share it.

The guide is a framework-free static website. It offers one practical route
from the first factory through Mission Completed, with optional paths,
production references, technology tooltips, and local checklists for readers
who want additional detail.

On narrow screens, **Route** opens the phases and expedition stages in a
scrollable sheet. **REF** opens references and **↑** returns to the top.
The desktop phase rail and existing section links remain available.
Phone dashboards stack their fields; wider reference tables have labelled
sideways scrolling. Production flows and headings wrap within the reading width.
Tap a technology name for scrollable details with a Close button. Checklist
text is tappable, and progress stays in the same browser-local record.

Version **3.2** is the four-language phone-support candidate: English,
Simplified Chinese, German and Japanese. It targets current
Android Chrome on Galaxy S23 Ultra class phones and current iOS Safari, with
360–480 CSS px portrait widths, landscape use, and 200% text enlargement.
Acceptance uses agent-reviewed Chromium/WebKit emulation and installed desktop
Chrome with mobile settings. It is not physical-device or branded iOS Safari
certification; OS fonts, browser chrome, and assistive technology can differ.
Desktop remains supported. Other mobile browsers and tablet-specific design
are outside this support promise. The owner controls production publication.
German quantities use decimal commas and grouping dots while preserving the English source values and units.

## Privacy and dependencies

The guide has no server-side code, accounts, cookies, or repository-supplied
analytics. Its scripts, data, styles, and images are stored locally in the
repository and can be reviewed before the guide is opened.

Checklist marks use one namespaced `localStorage` record in the reader's own
browser. They are never transmitted, and the reset control removes only that
record. All 66 checklist identities are explicit and stable across
language editions; the authoring inventory is in `localization/README.md`.

## Opening the guide locally

Generate `artifacts/site` with the authoring command below, then serve that
directory with any ordinary static web server. Open `/` and use the language
links for `/zh-CN/`, `/de/` or `/ja/`. Serving the repository root opens only the
English source. A local web server is required for technology tooltips because
browsers do not allow a local `file://` page to fetch the separate JSON data.

The guide fully supports Dyson Sphere Program Early Access `0.10.35.29057`.
The project owner confirmed that all existing validations pass and the guide
works unchanged after the update. See the
[game compatibility record](docs/PROJECT.md#game-compatibility) for the build
and assembly hash.

## Project documentation

For authoring checks, `scripts/Bootstrap-AgentEnvironment.ps1` provisions pinned
Prettier and Playwright Chromium/WebKit in ignored local tools. After activating
its helper, `node scripts/validate-phone.mjs --help` describes the repeatable
browser checks. These tools are not deployed with the website.

Localization authoring pins `parse5` 8.0.1 in the pnpm lockfile. Install with
`pnpm install --frozen-lockfile --ignore-scripts`, then run
`node scripts/build-site.mjs artifacts/site` with a new or empty output folder.
`node scripts/validate-localization.mjs artifacts/site` checks source coverage,
catalog freshness and exact generated bytes. See
[`localization/README.md`](localization/README.md) for private segment previews
and upkeep. Catalogs, parser packages and game locale files never deploy.

The manifest enables all four complete editions. Each translated catalog has
1,537 messages and eight UI strings, reviewed and agent-validated through
ML-27. CI rejects incomplete or stale translations and validates the extracted
package. Language links
preserve the current section and share checklist progress on the same origin.
There is no language redirect or preference tracking. Production publication
remains the owner's action.
