# Pending Guide Design Leftovers

**Status:** Scheduled for breakdown after the current roadmap stories. This
record is not authorization to implement the concerns below.

These concerns were preserved from the 2026-08-09 guide review but are not yet
bounded enough for implementation stories. Under
[`ROADMAP.md`](ROADMAP.md), they become planning input only after both active
correction stories are accepted.

## Expedition intra-navigation

ILS and WARP are expedition phases and structural outliers. Their unusual
length makes it harder to resume at the correct substep. A complete response
will probably combine several navigation or state cues.

Before creating a story, identify the actual resumption failures and compare
approaches without assuming that the normal phase template fits an expedition.

## Expedition interphase navigation

Optional expeditions can become useful before their numbered position at the
end of the guide. Their entry timing and return destination depend on the
player's current phase and reason for leaving it.

Keeping them at the end permits free entry and exit, but loses structural
information that prose cannot fully restore. A future structural story needs
an approved model for:

- when an expedition is offered;
- whether navigation should branch;
- where each entry path returns;
- how numbering communicates optional timing;
- which public anchors and saved state must remain stable.

## Complex-layer progressive disclosure

Some complex areas allow explanation, research structure, and reference
figures to enter the orientation layer. This is not one document-wide defect.

Inventory concrete reader failures first, then create separate case-specific
stories. Do not authorize a broad simplification or dashboard rewrite from
this observation alone.

## Prose-icon saturation

Agentic editing has repeatedly reintroduced inline prose icons after local
cleanup. A durable response requires an approved placement policy rather than
another removal pass.

Before creating implementation stories:

1. define which document surfaces benefit from item and technology icons;
2. identify surfaces where icons interfere with reading rhythm;
3. decide whether prevention belongs in the materializer, validation, or both;
4. separate future-growth prevention from cleanup of existing markup.

Recurring materialization must not become an editorial migration mechanism.

## Mobile priority

Mobile presentation is a low product priority. The expected reader uses a PC
browser through alt-tab or a second monitor while playing DSP.

Do not create mobile-polish stories unless narrow behavior blocks basic access
or exposes a structural defect shared by the desktop presentation.
